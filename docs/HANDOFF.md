# HANDOFF — لعبة «مكعبي»: الحديقة السحرية

وثيقة تسليم للانتقال إلى Claude Code. اقرأها كاملة قبل أي تعديل.

## 1. ما هو المشروع

لعبة بناء ثلاثية الأبعاد للأطفال تعمل في المتصفح (Three.js). صاحب المشروع محمد، معماري ومطوّر، يبنيها لابنته (8 سنوات). يتواصل بالعربية، فاكتب له بالعربية وبجمل قصيرة.

الرؤية البعيدة: عدة عوالم (زهور وقصور، جزيرة مغامرات، بحر، حروف عربية...)، ولكل عالم مراحل. الموجود الآن عالم واحد ومرحلة واحدة: **الحديقة السحرية**.

## 2. مبادئ لا تُكسر

- لا عنف، لا أعداء، لا أسلحة، لا دردشة، لا إعلانات، لا مشتريات.
- لا مؤقتات، لا عقوبة على الخطأ، لا خسارة نجوم، لا مكافآت عشوائية، لا سلاسل دخول يومية.
- البناء الحر متاح دائمًا. النجوم تفتح قطعًا جديدة فقط.
- واجهة عربية RTL، أزرار كبيرة، نصوص قصيرة. النصوص الحالية بصيغة المؤنث.
- مكّو (الروبوت المرشد) يتكلم قليلًا ولا يقاطع اللعب. التلميح يأتي عند الطلب فقط.
- التحقق من المهام وظيفي (عدّ، وجود قطعة)، وليس مقارنة بنموذج ثابت.
- النسخة الأولى صغيرة. لا تضخّم النطاق ولا تبنِ أنظمة لم تُطلب بعد.

## 3. الحالة الحالية

نموذج أولي يعمل، في ملفين:

| الملف | المحتوى |
|---|---|
| `index.html` | كل شيء: HTML + CSS + JavaScript في ملف واحد (نحو 600 سطر) |
| `three.min.js` | Three.js r160 (UMD)، يُحمَّل محليًا بمسار نسبي |

منشور كصفحة خاصة: https://claude.ai/artifact/6qdFLRgWAegzj9gzd1mV3g

اختُبر في Chrome بلا واجهة (Playwright): الزرع، المقعد، النجوم، الحفظ والاستعادة بعد إعادة التحميل. **لم يُختبر على آيباد أو هاتف حقيقي، ولم تُسمع الأصوات فعليًا.**

### الميزات
- **البناء:** 8 مكعبات، 6 أنواع زهور، 9 قطع زينة. الضغط على قطعة غير مكعبة بالقطعة نفسها يدوّرها 90°، وبقطعة أخرى يستبدلها.
- **البداية:** حديقة نصف مبنية (سياج، بوابة، ممر، ساحة، أشجار) من الدالة `defaultWorld()`.
- **المهمة:** 3 نجوم: 4 أنواع زهور / مقعد / 12 زهرة. النجوم تفتح: نافورة (1)، فانوس (2)، أرنب (3).
- **الحياة:** فراشات بعدد يتبع الزهور، غيوم، نهار وليل، فوانيس تضيء ليلًا (4 أضواء كحد أقصى).
- **الأصوات:** WebAudio مولّدة بالكود (نغمات)، مع عصافير وصراصير، وزر كتم.
- **تراجع/إعادة** (200 خطوة)، **حفظ تلقائي** في `localStorage`.
- **مكّو:** ضغطة = الهدف التالي، ضغطة ثانية = شرح + وميض على التبويب المناسب.

## 4. بنية الكود داخل `index.html`

الكود مقسّم بتعليقات `/* ---------- ... ---------- */` بهذا الترتيب:

1. **geometry helpers:** `P`, `b` (صندوق قاعدته على ارتفاع معيّن), `cyl`, `M` (دمج الأجزاء في BufferGeometry واحدة بألوان رؤوس).
2. **TYPES:** تعريف كل قطعة: `name`, `cat` (`cube` | `flower` | `decor`), `geo()`, واختياريًا `stars` (عدد النجوم للفتح), `flat`, `glow`.
3. **renderer & scene:** إضاءة، ظلال، أرضية شطرنجية، بحر، غيوم.
4. **instanced meshes:** `InstancedMesh` واحد لكل نوع. `rebuild(type)` يعيد بناء نوع واحد عند تغيّره (مجموعة `dirty`).
5. **starting garden:** `defaultWorld()`, `loadWorld()`.
6. **save:** `save()` مؤجل 400ms، و`saveNow()` عند إخفاء الصفحة.
7. **sound:** `beep()` و`sfx.*` و`ambience()`.
8. **editing with undo:** كل تعديل `op = [{k, a: before, b: after}]`. `commit(op)` هو المدخل الوحيد لتغيير العالم.
9. **picking:** `pick()` يمشي الشعاع خلية خلية في الشبكة (DDA) ويرجع الخلية والوجه. `targetFor()` يحدد أين توضع القطعة وقواعد الدعم.
10. **camera & input:** كاميرا مدارية مكتوبة يدويًا، Pointer Events، تمييز النقرة عن السحب (9px / 700ms)، قرص بإصبعين.
11. **mission:** `GOALS` (نص، حد، دالة قيمة، تلميح)، `checkGoals()`.
12. **living garden:** فراشات وأضواء الفوانيس، `applyNight()`.
13. **palette:** صور مصغّرة تُرسم بـ renderer صغير مؤقت، `buildPalette()`.

### البيانات
- الشبكة: `N = 20` (x, z)، `H = 10` (y). الأرض ليست مكعبات، والخلية `y = 0` فوقها مباشرة.
- العالم: `Map` مفتاحه `K(x,y,z) = x + N*(z + N*y)` وقيمته `{t, r}` (النوع والدوران 0–3).
- الحفظ: المفتاح `makabi-garden-v1`:
  ```json
  { "v": 1,
    "voxels": [[x, y, z, "type", r], ...],
    "state": { "stars": [true,false,false], "night": false, "muted": false, "seenIntro": true, "winShown": false } }
  ```
- للتجربة من الـ console: `window.__garden` (`tap`, `pick`, `voxels`, `state`, `cam`, `stats`).

## 5. قرارات متخذة وأسبابها

| القرار | السبب |
|---|---|
| ملف واحد بلا build | نموذج سريع يُنشر كصفحة واحدة |
| `InstancedMesh` لكل نوع مع هندسة مدموجة | draw call واحد لكل نوع، مناسب للآيباد |
| التقاط بالمشي في الشبكة بدل raycast على الـ meshes | أدق، يعطي الوجه مباشرة، ومساحة لمس أكبر للطفل |
| كل قطعة تشغل خلية واحدة | تبسيط؛ لا توجد قطع متعددة الخلايا |
| الزهور والزينة تحتاج أرضًا أو مكعبًا تحتها، وتسقط للأسفل تلقائيًا | سلوك مفهوم للطفل |
| `localStorage` بدل IndexedDB | يكفي لحجم العالم الحالي (4000 خلية كحد أقصى) |
| Three.js كملف محلي | سياسة الصفحة المنشورة تمنع أغلب المصادر الخارجية |

## 6. حدود ونواقص معروفة

- الحفظ محلي في المتصفح: لا مزامنة ولا تصدير/استيراد.
- لا اختبار على أجهزة حقيقية؛ الأداء على آيباد قديم غير معروف.
- السياج لا يتصل تلقائيًا بجيرانه، ويُدوَّر يدويًا.
- لا حركة عند وضع القطعة (تظهر فورًا)، والنافورة بلا ماء متحرك.
- الأصوات نغمات مولّدة، ولا موسيقى.
- لا شاشة اختيار عوالم ولا «ساحة الأحلام» بعد.
- بناء `three.min.js` (UMD) أُعلن إيقافه في إصدارات أحدث؛ عند الانتقال إلى مشروع بـ bundler استخدم ES Modules.

## 7. الخطوات المقترحة في Claude Code (بالترتيب)

1. **مستودع ومشروع:** Git + Vite + TypeScript + `three` من npm. انقل الكود إلى وحدات **دون تغيير السلوك**:
   `types.ts` (القطع)، `world.ts` (البيانات + undo)، `render.ts` (instancing)، `pick.ts`، `input.ts`، `mission.ts`، `audio.ts`، `ui.ts`، `save.ts`.
2. **نشر:** رابط ثابت (GitHub Pages أو Netlify) يُفتح على الآيباد.
3. **اختبار مع الطفلة** على الجهاز الحقيقي، وتسجيل أين تتعثر. هذا يحدد كل ما بعده.
4. **المحتوى كبيانات:** نقل `TYPES` و`GOALS` و`defaultWorld` إلى ملفات بيانات، لتُضاف مرحلة جديدة بلا لمس المحرك.
5. **المرحلة الثانية «قصر الأحلام»:** أبراج، نوافذ، أبواب، وتحدي تماثل (فحص تطابق الخلايا على جانبي محور).
6. **تحسين الشكل:** خامات مرسومة للمكعبات، مجسمات glTF للزينة، صور للشخصيات. الهدف الاقتراب من الصورة التصورية دون خسارة السلاسة.
7. **الحفظ:** IndexedDB + تصدير/استيراد ملف + ترقيم إصدارات مع ترحيل `v1`.
8. **لاحقًا:** شاشة العوالم، جزيرة المغامرات، ثم مملكة الحروف (النص العربي يُرسم على Canvas ويُستخدم كـ texture، لأن `TextGeometry` لا يشكّل العربية).
